# Двери и окна

`@deathwarriors/game-core/openings` проверяет и открывает существующий проём по стабильному ID.
`checkOpeningInteraction` возвращает допустимость и причину отказа без изменения мира;
`openOpening` повторяет проверку по текущему состоянию и синхронно меняет только `state` на `open`.
Проверяются живой размещённый актор, закрытое неукреплённое состояние, матрица объекта 5×5
и supercover. Целевая дверь сама себе линию не перекрывает.

Враг может открыть дверь или окно без знания защитника за ними. Защитнику доступны только
двери и требуется `defenderCanOpen`: вызывающий AI проверяет отсутствие открытого пути
к известным противникам и булевый `leadsToEnemy` по §5.5. Без этой проверки открытие
защитником отклоняется. API не выбирает кандидата, не расходует RNG и не ранжирует путь
за дверью; выбор целей и маршрутов относится к AI.

В обработчике `runUnitTurn` вызов `openOpening` выполняется один раз для действия `INTERACT`.
Слот расходует сам цикл хода, поэтому после первого открытия остаётся второе действие.
Ночного закрытия, ремонта и дневной экономики в этом API нет. Проходимость читает состояние
карты непосредственно: после открытия или разрушения отдельная инвалидация не нужна.

`canAttackOpening` допускает базовую атаку только врагом по закрытому укреплённому проёму
в маске атаки и с чистой линией. Попадание по укреплению гарантировано; обработка урона
и разрушения находится в домене `damage`. При HP=0 он сохраняет сам проём, укрепление
и прикреплённые эффекты, меняя состояние на `destroyed`. Прямой CELL_DAMAGE по клетке
не является выбором базовой атаки юнита.
