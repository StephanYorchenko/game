# Индивидуальное обнаружение ловушки

Публичный вход — `@deathwarriors/game-core/trap-discovery`.
`tryDiscoverTrap(world, enemyId, trapId, probability, rng, options?)` выполняет одну
явно адресованную попытку. Условия до RNG: живой размещённый враг, существующая ещё
неизвестная ему ловушка, отсутствие доступного для атаки защитника и наличие полного
пути к позиции атаки какого-либо защитника по текущим знаниям и ограничениям.
Доступное укрепление само по себе не запрещает попытку; маршрут только к проёму
не заменяет требуемый путь к защитнику.

При успехе ID добавляется в `UnitState.knownTrapIds`. Проходимость и все существующие
поисковики автоматически учитывают этот список вместе с `MovementOptions.knownTrapIds`.
Знание не распространяется союзникам; потеря всех путей после успеха допустима.
Это JSON-состояние конкретного экземпляра юнита. Список может содержать ID уже удалённой
ловушки до конца ночи; `clearTrapKnowledge(world)` очищает его на границе ночи, включая
погибших. Принудительное перемещение сохраняет правила срабатывания ловушки.

Вероятность должна находиться в [0, 1]. Для промежуточного значения используется один
seeded nextFloat и сравнение roll < probability. Значения 0/1 определены без RNG;
недоступная попытка тоже не расходует случайность. Неверная вероятность/результат RNG
вызывает ошибку без записи знания.

Операция `discover_trap` содержит `trapId` и `probability: NumericExpression` и выполняется
только в TURN_START. Формула использует существующий ограниченный интерпретатор, без eval.
Runtime получает `trapDiscovery: { rng, getOptions?, onOutcome? }`; rng должен принадлежать
той же симуляции, getOptions разрешает актуальные ограничения ключевых слов.
onOutcome — необязательное наблюдение реально выполненной попытки. Неуспешный бросок
считается выполненной операцией; отсутствующая возможность попытки возвращает false.
Слоты действия обнаружение не расходует. Runtime-сервисы не сериализуются в WorldState.

## Конкретный пример для ревью, не глобальная политика

`example.json` задаёт одну постоянную способность TURN_START против конкретной ловушки
`snare-1` в тестовом коридоре: вероятность max(0, min(1, agility * 0.1)). Один экземпляр
способности делает одну попытку при каждом начале хода; после неудачи повторяет её
в следующий ход, после успеха известных целей не проверяет. Тестовый юнит имеет agility=5.

Эти формула, кандидат и повторы — параметры примера, а не утверждённое общее поведение
врагов. Ядро не выбирает глобальный радиус, порядок нескольких ловушек или лимит попыток:
это остаётся OPEN для конкретной способности/контента. Другой кандидат задаётся явно
другой операцией; сам движок не добавляет скрытых повторов или дополнительных кандидатов.

`trap-discovery.test.mjs` проверяет условия попытки, персональную проходимость, запирание,
формулу, повтор примера, очистку ночи, принудительный вход и журнал/JSON replay.
