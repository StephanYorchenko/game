# Пути до позиции действия

`@deathwarriors/game-core/pathfinding` использует BFS по допустимым ортогональным шагам конкретного юнита. Цель `attack` задаёт клетку атаки; конечная позиция проверяется его фиксированной attackMask и supercover. Цель `interact` задаёт клетку объекта и его отдельную interactionMask. Путь заканчивается на ближайшей позиции, откуда доступно нужное действие. Входить в занятую клетку цели не требуется. Если действие доступно уже сейчас, расстояние 0 и steps пуст.

`getActionDistance` возвращает минимальное число шагов либо undefined без RNG. Слой целеполагания может сравнить удалённые цели, выбрать допустимую ближайшую, затем вызвать `findActionPath` для неё. Сам модуль не решает, кто известен защитнику, какую дверь можно открыть или какие типы целей конкурируют; это ENG-20–23.

Техническая конвенция случайного выбора: BFS перечисляет соседей север, восток, юг, запад; сохраняет все минимальные предшествующие клетки. Сначала seeded RNG равновероятно выбирает одну из ближайших конечных позиций в порядке их обнаружения. Затем маршрут восстанавливается назад, на каждом разветвлении равновероятно выбирая предшественника в порядке обнаружения. Это случайный выбор кратчайшего пути, без обещания равных вероятностей для всех полных последовательностей шагов. Единственный вариант и отсутствие пути не расходуют RNG. Более длинный путь случайность выбрать не может.

Учитываются ограничения directions/allowWindows, знание ловушек, занятость и запрет выхода защитника наружу из общего модуля движения. При проверке линии из будущей позиции исходное тело самого актёра не считается оставшимся на старой клетке блокером; остальные юниты продолжают блокировать. Исключения ключевых слов передаются через options.line. Мир не меняется, возвращённые координаты отделены от него.

Расстояние не ограничивается текущей скоростью: это метрика маршрута, а не исполнение одного MOVE. Исполнение, динамический бюджет, ловушки и перепланирование относятся к ENG-24–25. Открытие закрытых дверей в BFS не симулируется; потенциальная TRUE/FALSE-проверка дверей защитника будет отдельным слоем ENG-21.
