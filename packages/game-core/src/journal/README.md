# Детерминированный журнал и повтор

`@deathwarriors/game-core/journal` хранит JSON-записи с последовательным номером,
раундом, ходом, владельцем, слотом и фазой. Здесь нет времени компьютера, таймеров,
глобального RNG или UI. `EventJournal.append` копирует данные; `snapshot` возвращает
независимую копию. Не-JSON значения и циклы отклоняются, а не теряются при сериализации.

`runJournaledTurn` подключает существующий цикл хода и общую очередь CELL_DAMAGE.
Он записывает пустые фазы, выбранное действие, экземпляры эффектов, результаты операций,
изменения HP, исходы урона, смерти и пропущенные эффекты погибших владельцев.
Действие должно быть JSON DTO и содержать ID цели/клетку, нужные для диагностики.
Неосуществимая операция помечается `operation_unavailable` вместе с полным описанием
операции и контекстом; это не ошибка и не отмена остальных операций эффекта.

Для исполнения вне хода доступны `createJournalRuntime` (операции) и
`createJournalDamageQueue` (общая очередь). Наблюдатели не меняют симуляцию.
Действия должны использовать наблюдаемые операции/очередь; собственные атомарные
команды и решения AI добавляют записи через `append` с устойчивыми ID и причинами.
Журнал не заменяет исполнитель действий и не выбирает цели.

`journalRng` оборачивает единый seeded RNG без дополнительных бросков. Записываются
метод, аргументы, результат/индекс выбора, упорядоченные кандидаты и состояние до/после.
Кандидаты `pick` должны быть JSON-данными; их проверка проходит до расходования RNG.
Вызов `snapshot` не расходует RNG и не добавляет запись. Для одного вызова `d6`/`pick`
создаётся одна запись, без дублирования внутреннего `nextInt`.

`recordSimulation(initial, seed, runner)` сохраняет независимые копии исходного сценария,
журнала, итогового состояния и RNG. В `initial` вызывающий слой передаёт **все** входы:
мир, экземпляры эффектов, очередь, счётчики событий и версию контента/конфигурации.
`runner` получает копию initial, журнал и RNG; возвращает полный итоговый снимок.
`replaySimulation(recording, runner)` заново выполняет тот же runner и сообщает первое
расхождение `entries[n]`, `final` или `rng`. Порядок ключей объекта не влияет на сравнение,
порядок массивов/записей влияет. Это повтор исходного запуска, а не выполнение кода из JSON
и не сохранение незавершённой очереди. Для восстановления нужен тот же runner/контент.

Полный журнал — внутренний диагностический артефакт: он может содержать внешние позиции,
RNG-кандидатов и невидимые эффекты. `publicSnapshot` выдаёт **только явно public-записи**
и заново нумерует их без промежутков. Привязку к видимости карты выполняет вызывающий слой;
исходный/итоговый мир полной записи нельзя передавать игроку вместо этой проекции.

## Причинные цепочки

Записи эффектов, операций и событий сохраняют cause, если он задан.
Пропущенный повтор definitionId имеет причину reaction_cycle, отдельно от owner_unavailable.
Ancestry — независимые JSON-массивы, поэтому сохранённая запись воспроизводится без
глобального набора использованных способностей или зависимости от времени.
