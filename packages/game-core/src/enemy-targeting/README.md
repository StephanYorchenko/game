# Цели маршрута врага

`@deathwarriors/game-core/enemy-targeting` сравнивает живых защитников и закрытые двери/окна
по кратчайшему допустимому пути **до позиции нужного действия**. По обычному проёму нужен
INTERACT с матрицей объекта, по укреплению/юниту — ATTACK с маской атакующего.
Знать защитника за проёмом не требуется. Открытый/разрушенный проём не является целью.

`getEnemyRouteTargets` не расходует RNG, возвращает только достижимых кандидатов и не меняет
мир. Стабильный порядок: юниты мира, затем проёмы по строкам карты. `selectEnemyDestination`
выбирает минимум distance, при равенстве — seeded RNG из общего набора ближайших типов
(решение автора 05.11), затем кратчайший маршрут. Отдельного приоритета открываемости нет:
ближнее укрепление не уступает дальнему обычному входу. Это не случайный выбор удалённой цели
из всех кандидатов и не правило немедленного INTERACT.

Ограничения движения, известные конкретному врагу ловушки и supercover передаются через
PathOptions. Запрет проходить через окно не запрещает воздействовать на окно: «Гигант»
может открыть/атаковать закрытое окно из допустимой позиции, но не пройти в его клетку.
Поэтому выбор окна не требует последующего маршрута через него к защитнику.

Для обычной атаки по защитнику допустимая позиция врага должна быть внутри (`actorArea`
в описании цели pathfinding). Это сохраняет OPEN внешних атак по юнитам; снаружи по укреплению
атаковать можно. Промежуточные шаги пути могут идти по внешней территории.

При отсутствии достижимой цели или допустимого актора возвращается undefined без RNG.
Модуль не выбирает частичный маршрут к недоступной преграде и не придумывает точку ожидания:
это остаётся OPEN. Нулевой MOVE и приоритет ATTACK → INTERACT → MOVE подключает слой действий.
