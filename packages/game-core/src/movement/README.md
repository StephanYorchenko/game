# Проходимость

`canEnterCell(world, unit, position, options)` проверяет саму клетку, `canStep` дополнительно требует один ортогональный шаг из текущей позиции. `getStepDestinations` использует ту же проверку и возвращает допустимых соседей в порядке север, восток, юг, запад. Эти функции не меняют состояние и не расходуют RNG.

Ограничения ключевых слов передаются через `MovementOptions`: `directions` ограничивает направления (пустой массив запрещает движение), `allowWindows: false` запрещает оконные клетки независимо от состояния проёма. Имена ключевых слов и классов внутри модуля не интерпретируются: например, ограничения «Гиганта» разрешает вызывающий слой контента.

Для защитников все ловушки известны, внешние клетки запрещены. Для врага учитываются
индивидуальные `UnitState.knownTrapIds` и дополнительные ограничения `MovementOptions.knownTrapIds`;
неизвестная ловушка допускается в маршрут. При реальном входе её сначала уничтожает атомарный
шаг, поэтому две размещённые сущности не сосуществуют. Любой другой юнит блокирует клетку
независимо от стороны.

Закрытый проём непроходим до отдельного действия открытия/разрушения. Скорость, оставшиеся шаги и принудительное перемещение не относятся к этой проверке обычного шага: их обрабатывает исполнитель действия. Граница здания берётся из явного `area` клетки, без вывода по соседним стенам.

## Ленивое действие MOVE

`executeMove(runtime, actorId, target, rng, getOptions?)` возвращает итератор пакетов
`ExecutableEffect[]`, совместимый с `TurnHandlers.executeAction`. В runtime необходимо добавить
`movement: createMoveState()`. Цель — `{ kind: "unit" | "opening", id }` либо `undefined`.
Выбор ближайшей цели остаётся у политик сторон; итератор не выбирает новую цель сам.

Каждый пакет содержит ровно один атомарный эффект с операцией `move_step`. В контексте зафиксирована
целевая клетка. Потребитель ставит пакет в общую очередь и полностью вызывает `drain()` до следующего
`next()`; `runUnitTurn` уже соблюдает этот порядок. Сам вызов `next()` юнита не перемещает.
Операция повторно проверяет исходную позицию, проходимость и бюджет. Дубли и устаревшие пакеты
не двигают юнита повторно. Неразрешённый предыдущий шаг вызывает ошибку протокола.

После последствий читаются текущие `movement`, позиции и ограничения, затем строится новый
кратчайший путь к позиции нужного действия. `getOptions()` предоставляет актуальные знания,
ограничения движения и исключения LOS. Выполненные шаги подтверждаются в `MoveState`, поэтому
последующее принудительное смещение не меняет уже потраченный бюджет. Состояние содержит JSON-данные;
между действиями сохраняется счётчик ID, а активная запись удаляется при завершении/`return()`.

Любая допустимая атака или доступное взаимодействие с выбранным проёмом завершает MOVE штатно,
без атаки/открытия в том же слоте. Изменившаяся позиция выбранной цели учитывается заново.
Вызывающий слой может явно изменить `movement.active[].target`; автоматический retarget и точка
ожидания у непроходимой блокады остаются OPEN. Без полного пути либо цели выдаётся 0 шагов.
Нулевая скорость также даёт 0 шагов, сохраняя обычные ACTION_END и расход слота.

Ловушка удаляется в атомарном шаге до переноса; её DEATH разрешается после целого эффекта
и до следующего шага. Контракт — в [домене traps](../traps/README.md).
Явные прерывания действия/хода читаются из runtime.turnControl между шагами. `return()` позволяет
исполнителю прекратить выдачу шагов и очистить активную запись без добавления новых фаз.
