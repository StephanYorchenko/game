# Просмотр карты DeathWarriors

Первый срез UI-MVP: браузер показывает вручную заданный сценарий через публичный API
`@deathwarriors/game-core`. Сценарий проходит `loadWorld`. Поверхность, область здания,
структура и размещённая сущность отображаются отдельными слоями. Все состояния дверей
и окон, укрепления, HP юнитов и ловушки представлены в демо.

## Запуск

Из корня workspace, с закреплённым pnpm:

```sh
pnpm install --frozen-lockfile
pnpm dev:ui
```

Vite выводит локальный адрес. `dev:ui` сначала собирает публичный API core.
После изменения core нужна его повторная сборка. UI — обычные TypeScript, DOM и CSS;
правила движения, геометрии и боя остаются в core. Обратной зависимости core → UI нет.

```sh
pnpm --filter @deathwarriors/game-ui exec playwright install chromium
pnpm check
pnpm test:ui
```

`pnpm check` проверяет оба пакета в порядке зависимостей. `test:ui` собирает API core
и UI, затем запускает только браузерные тесты UI. Тесты core в этой команде не запускаются.
Для Linux Playwright может потребовать `playwright install --with-deps chromium`.
Production-сборка: `pnpm build`; просмотр: `pnpm --filter @deathwarriors/game-ui preview`.

## Контракт отображения

`createMapView(root)` из `src/map-view.ts` возвращает `render(world)` и `destroy()`.
`render` принимает корректный `WorldState`, не меняет его и заменяет прежнюю сетку
новым снимком, включая изменение размера и освобождение клетки. Сначала валидируйте
неизвестные данные через `loadWorld`/`parseWorld` из core. Состояние не сохраняется
в DOM как источник игровых данных. Размер и счётчики в оболочке пока относятся к демо;
будущий контроллер загрузки/симуляции обновит их вместе с новым снимком.

Поверхность (`floor`/`ground`) не выводится из `inside`/`outside`: это независимые поля.
У юнита на проёме сохраняются оба слоя. `alive` берётся из core отдельно от HP.
ID выводятся безопасным текстом в доступной подписи и подсказке клетки. Таблица имеет
заголовки координат и доступную подпись каждой клетки. На узком экране прокручивается
карта; область доступна с клавиатуры.

Клик, Enter и пробел выбирают клетку. Стрелки перемещают отдельный фокус в границах
карты; только одна клетка участвует в Tab-порядке. Выбор отмечен рамкой и галочкой,
фокус — белым пунктиром. Инспектор показывает реальные ID/definitionId, характеристики,
слой проёма и укрепление. Нулевой HP сам по себе не скрывает ещё живого юнита.

`createMapView(root, { onSelect })` передаёт в обработчик позицию, клетку и её обитателя
либо `null`, когда выбора нет. `render` обновляет инспектор по выбранной координате,
а при уменьшении карты сбрасывает исчезнувший выбор. Фокус восстанавливается только
если до обновления он был внутри карты. `destroy` очищает карту и выбор.

JSON-сценарии — UI-03, оверлеи API core — UI-04,
управление ночью и журнал — UI-05 после ENG-32/ENG-33. Отображение открытого состояния
проёма сейчас не требует готовности действия открытия ENG-18. Сценарий не задаёт
новых правил, генерации мира или скрытой информации.

## Проверки и прототип

Playwright проверяет настоящую страницу в Chromium: слои и состояния, обновление снимка,
юнита на открытом проёме, освобождение клетки после смерти, смену размера карты,
безопасный ID, независимость области/поверхности и прокрутку на экране 390 px.
Отдельный smoke-тест проверяет production-сборку. В CI джоба `ui` собирает API core
без запуска core-тестов и выполняет UI-проверки независимо от джобы `checks`.

[Карточка UI-01](https://trello.com/c/Y5itUP8E).
[Прототип Figma](https://www.figma.com/design/IZgkNnLgCTydbfWBSGp3un?node-id=3-2).
Прототип — ориентир компоновки и палитры, его редактируемые клетки не являются
источником состояния игры. Дальнейшие экраны уточняются в соответствующих UI-задачах.
