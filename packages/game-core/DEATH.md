# Граница смерти

`createDeathQueue(runtime, getTurnOrder)` из `@deathwarriors/game-core/death` подключает фиксацию смерти к afterEffect. Все операции эффекта завершаются раньше проверки HP. Юнит с alive=true и временным HP=0 может получить лечение в следующей операции того же эффекта. После завершения эффекта оставшийся HP=0 переводит alive в false, освобождает клетку и планирует собственный стек DEATH.

`commitUnitDeaths(runtime, turnOrder)` также доступна для границы независимого события, например будущего CELL_DAMAGE. Она возвращает записи смертей с сохранёнными координатами и подготовленные эффекты; вызывающий слой вставляет их в очередь через emit. Партии разных границ не объединяются.

При нескольких смертях порядок берётся из актуального массива ID очереди ходов. Перед удалением ID сохраняются ранги и клетки всех погибших, затем освобождаются все их клетки. Только после фиксации всей партии создаются снимки DEATH в порядке очереди ходов, внутри каждого — новые → старые. Порядок операций, обход world.units и исходные значения инициативы не используются для ранжирования. Getter позволяет читать заменённую/изменённую очередь, включая будущие вставки призыва. Погибающий участник должен уже находиться в ней; отсутствие или дубликат ID — ошибка состояния, а не повод молча выбрать другой порядок.

Погибшие ID удаляются из переданного массива на месте; сами UnitState остаются в мире для адресации и чтения сохранённых характеристик. Характеристики и локальные экземпляры не сбрасываются, обратные операции не запускаются. Повторная проверка не фиксирует ту же смерть заново. Обычные эффекты погибшего и уже поставленные завершающие фазы пропускает проверка владельца в очереди; собственный DEATH разрешён. Другие владельцы продолжают исполнение, а новые смерти из DEATH создают следующую вложенную партию.

isOwnerAlive проверяет alive у юнита, наличие ловушки и неразрушенное состояние проёма; само нулевое HP не выключает владельца посреди эффекта. Полный жизненный цикл ловушек и укреплений подключается в ENG-18/25. Этот модуль фиксирует только смерти юнитов. Фактический запуск/отмена слотов и завершающих фаз хода относится к ENG-14; он должен проверять жизнь перед планированием следующего этапа. Воскрешения нет.
