# Воспроизводимый RNG

```ts
import { createSeededRng, restoreSeededRng } from '@deathwarriors/game-core/random';

const rng = createSeededRng(42);
const die = rng.d6();
const door = rng.pick(candidates);
const restored = restoreSeededRng(JSON.parse(JSON.stringify(rng.snapshot())));
```

## Протокол pcg32-v1

Алгоритм — PCG XSH-RR 64/32 с фиксированным stream 54. Числовой seed — целое от 0 до 2^32 − 1, включая 0. 64-битная арифметика выполняется точно через BigInt; снимок хранит состояние строкой и совместим с JSON.

Переход и инициализация сверены с [описанием PCG32](https://www.pcg-random.org/using-pcg-c-basic.html). Контрольная последовательность для seed 42 закреплена в тесте.

- `nextUint32()` возвращает число из [0, 2^32), `nextFloat()` — из [0, 1). Каждый расходует один результат генератора.
- `nextInt(n)` возвращает целое из [0, n), где 1 ≤ n ≤ 2^32. Полный хвост 32-битного диапазона, не кратный n, отбрасывается; повторные попытки расходуют дополнительные результаты. При n = 1 результат 0 не расходует RNG.
- `d6()` вызывает `nextInt(6) + 1`.
- `pick(items)` выбирает равновероятный индекс; пустой массив возвращает undefined, единственный кандидат возвращается без расхода RNG. Массив не сортируется и не меняется. Повторы в массиве — отдельные кандидаты.
- Порядок кандидатов — часть состояния: вызывающая логика передаёт стабильный массив, например фильтрует сериализованный список сущностей с сохранением порядка. Порядок не должен зависеть от UI или времени.
- Некорректные аргументы не расходуют RNG. `snapshot()` не расходует RNG и возвращает отдельный объект; восстановление не повторяет инициализацию seed.

В одной симуляции все случайные решения должны использовать переданный экземпляр `SeededRng`. Глобального генератора, чтения времени и Math.random в модуле нет. Изменение алгоритма, stream, инициализации или правил расхода требует новой версии протокола, чтобы старые повторы не менялись молча.
