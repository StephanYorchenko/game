# Срабатывание ловушки при перемещении

Обычный `move_step` и принудительный `move_unit` атомарно удаляют ловушку с фиксированной клетки,
затем пытаются перенести юнита. Удаление не откатывается, если перенос оказался невозможен:
это последовательность независимых осуществимых операций по №105. Обычный маршрут по-прежнему
исключает известные ловушки; принудительный перенос защитника также вызывает срабатывание.

Очереди `createOperationQueue` и `createDamageQueue` собирают удалённые ловушки до конца целого
родительского эффекта. Только затем берут снимки DEATH: последующее снятие оригинального эффекта
родителем учитывается. Дочерние эффекты наследуют причинную цепочку, исполняются после родителя
и до запроса следующего шага MOVE. Постоянные записи способностей не удаляются автоматически.

У ловушки нет обязательного урона или травмы. Контент задаёт DEATH-эффекты: `create_damage_event`
бьёт семантическую клетку, `occupant` выбирает её текущего обитателя для изменения характеристик,
лечения или добавления эффекта. Пустая клетка даёт пустой набор. Самостоятельного обязательного
события `trap_triggered` нет. Смерть вошедшего разрешает общая очередь; изменение movement влияет
на оставшуюся часть того же действия.

`move_unit` переносит выбранных живых юнитов в клетку текущего контекста. Абсолютные координаты
в конфиге операции не задаются. Он не расходует бюджет обычного MOVE и не требует смежности
или разрешённого обычным движением направления; стены, закрытые проёмы, занятость и запрет
выхода защитника наружу сохраняются. Нет контекстной клетки — операция пропускается.
Особые переносы сквозь стены и обмен местами не вводятся.

Интеграционные сценарии лежат рядом в `traps.test.mjs`: очередь, скорость, смерть, принудительный
вход, граница снимка DEATH, причинность и JSON replay. Прерывания действия/хода читают control текущего исполнителя; интеграция с MOVE проверена в домене turn.
