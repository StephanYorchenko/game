# Очередь атомарных эффектов

`ExecutionQueue<Operation>` из `@deathwarriors/game-core/execution` исполняет подготовленные эффекты синхронно. `enqueue` добавляет исходные эффекты в конец, `drain` разрешает очередь до опустошения. Тип операций и их интерпретатор передаются через `ExecutionHooks`; интерфейс не зависит от DOM или формата контент-пака.

Перед обычным эффектом `isOwnerAlive(ownerId)` вызывается ровно один раз. Эффект собственного стека смерти (`source: "death"`) проходит независимо от жизни владельца; этот признак назначает планировщик стека смерти, не произвольная операция контента. Нулевой HP сам по себе не заменяет проверку `alive`.

Для каждой операции заново вызывается `canExecute` по текущему состоянию. `false` пропускает только эту операцию, затем исполнение продолжается без отката. Все операции эффекта завершаются до запуска последствий. `context.emit(A, B)` накапливает последствия в порядке вызовов: если ранее ожидал C, получится A, B, C. Если A породит D, порядок продолжения будет D, B, C.

`afterEffect(context)` вызывается один раз после всех операций прошедшего проверку эффекта, включая пустой. Это граница интеграции ENG-12: там фиксируется смерть и через тот же `emit` планируется её стек. Саму фиксацию смерти, порядок нескольких погибших и локальные LIFO-стеки очередь не реализует. Тесты границы используют минимальный обработчик смерти, а не объявляют её полную реализацию.

Записи и массивы операций копируются при enqueue/emit. Глубокую независимую копию данных операции и состояния эффекта готовит слой снимков локальных стеков (ENG-09); очередь не копирует объекты игрового мира и не синхронизирует их с локальными экземплярами. Обработчики синхронные; сохранённый контекст нельзя использовать после завершения эффекта. Повторный drain и прямой enqueue из обработчика запрещены, последствия добавляются через emit.

Исключение из обработчика означает ошибку реализации/контента, а не невозможную игровую операцию. Оно прерывает drain и делает экземпляр очереди непригодным для продолжения; уже совершённые изменения мира не откатываются и не повторяются. Невозможность операции выражается через canExecute=false. Очередь — исполняющая инфраструктура; сериализация мира остаётся в данных, обработчики в JSON не сохраняются.

EntryQueue из того же домена задаёт общий планировщик без требований к владельцу или списку операций. ExecutionQueue сохраняет прежний API как адаптер эффектов. Домен damage использует общий планировщик для смеси эффектов и независимых CELL_DAMAGE; событие не подменяется способностью. Защита причинных цепочек и журнал относятся к ENG-35 и ENG-32.

## Наблюдение

`EntryQueue.observe` подключает необязательные `before`, `after`, `skipped` без второй
очереди исполнения. `after` вызывается после границы эффекта/события и до его последствий.
Наблюдатель не должен менять симуляцию. Ошибка наблюдателя, как и ошибка исполнителя,
останавливает очередь без отката; подключение во время исполнения запрещено.

## Копирование и проверка эффекта

Необязательные copyEffect и canExecuteEffect в ExecutionHooks позволяют доменному
исполнителю копировать метаданные и проверять причинную цепочку до начала эффекта.
Они не меняют общий порядок очереди и не вводят повторную проверку жизни между операциями.
