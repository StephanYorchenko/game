# Ленивое исполнение хода

`runUnitTurn(runtime, ownerId, getTurnOrder, handlers)` из `@deathwarriors/game-core/turn` исполняет один ход: TURN_START, затем два последовательных ACTION_START → выбор/действие → ACTION_END, затем TURN_END. У каждой фазы свежий независимый снимок локального стека. Очередь полностью разрешается перед переходом к следующей стадии.

chooseAction вызывается отдельно для каждого слота после всех последствий его ACTION_START. Возвращается описание ATTACK, INTERACT или MOVE с нужными обработчику данными. executeAction возвращает синхронный итератор пакетов атомарных эффектов. Пакет ставится в очередь и разрешается до запроса следующего пакета: изменения после шага доступны следующему next(). Пустой итератор MOVE штатно расходует слот и вызывает ACTION_END. Настоящий итератор движения подключён в ENG-24; выбор действия AI — в ENG-28.

По умолчанию на ход создаётся отдельная очередь с границей смерти ENG-12. createQueue позволяет подключить совместимую очередь с независимыми событиями; она должна исполнять все последствия и фиксировать смерть перед возвратом drain. Обработчики — доверенная инфраструктура движка, не JS из контент-пака; изменения мира должны выполняться атомарными эффектами очереди, а не скрыто в chooseAction.

Если владелец погиб в TURN_START или ACTION_START, действие не выбирается. После смерти внутри действия новые пакеты итератора не запрашиваются; DEATH и вложенные последствия уже разрешены очередью. ACTION_END и TURN_END погибшего не планируются. Если смерть случилась в ACTION_END, следующий слот не начинается. Другие владельцы внутри цепочки продолжают работать.

Для MOVE клетка старта копируется после выбора действия и перед исполнением. Она передаётся в контекст ACTION_END даже при нуле шагов. У остальных завершающих фаз нет неявной клетки; фазы атаки/защиты передаёт сам обработчик атаки.

Результат содержит статус и список инициализированных слотов с типами действий. Он не хранит методы обработчиков в мире и не пересчитывает инициативу. При входе ожидается состояние после завершённой предыдущей границы смерти. Прерывания не подменяют зафиксированную смерть и не запускают завершающие фазы погибшего.

## Наблюдение фаз

Необязательный `TurnHandlers.onPhase(phase, slot)` вызывается непосредственно перед
снимком фазового стека, включая пустые стеки. Для `TURN_START`/`TURN_END` слот равен `null`.
Наблюдение используется журналом и не должно менять состояние симуляции.

## Прерывания действия и хода

Операции `interrupt_action` и `interrupt_turn` принимают обычный селектор `target`.
Они воздействуют только на живого владельца уже исполняемого хода. Прерывание действия
действует в ACTION_START/исполнении действия и оставляет следующий слот; прерывание хода
отменяет все ещё не начатые слоты. Флаг будущему юниту или следующему ходу не сохраняется.

Текущий выданный пакет и его независимые последствия разрешаются полностью: оставшиеся
операции атома, CELL_DAMAGE, реакции и DEATH не отменяются. Исполнитель прекращает запрос
следующих пакетов итератора, вызывая его return и очистку MOVE. У живого владельца проходят
ACTION_END начатого слота и TURN_END; смерть сохраняет собственные правила завершения.

Прерывание хода в TURN_START оставляет только TURN_END. В ACTION_START слот уже начат:
его ACTION_END исполняется, но тип действия ещё не вычисляется и `result.actions` не получает
выдуманную запись. Прерывание действия в TURN_START/ACTION_END не действует; прерывание хода
в ACTION_END отменяет следующий слот, в TURN_END уже не имеет работы для отмены.
`status: "completed"` означает завершение живого владельца, включая завершённый с прерыванием ход.

`TurnControlState` содержит JSON-состояние текущего владельца, фазы и флагов. Необязательное
`runtime.turnControl: createTurnControl()` позволяет явно разделять его между исполнителями.
Если состояние не передано, runUnitTurn создаёт локальное и передаёт обогащённый runtime
через ActionContext и `createQueue(runtime)`. Фабрика пользовательской очереди должна использовать
полученный runtime, чтобы операции видели тот же control. Исходный объект runtime не изменяется.

Запись active очищается в finally, в том числе при ошибке обработчика. Вложенный ход на том же
control запрещён. Итератор executeMove также проверяет control между шагами и может вернуть
`reason: "interrupted"`; при использовании runUnitTurn его остаток закрывает сам исполнитель.
