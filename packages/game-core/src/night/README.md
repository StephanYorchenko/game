# Ночь из 13 раундов

Публичный вход — `@deathwarriors/game-core/night`.
`createNight(runtime, rng)` один раз разыгрывает инициативу и возвращает JSON NightState.
Runtime содержит world/effects, сохраняемые `movement: createMoveState()` и
`summoning: createSummoningState()`. Между вызовами используется тот же DamageState и
тот же seeded RNG; HP, характеристики, счётчики и постоянные эффекты не сбрасываются.

`stepNight(runtime, state, damage, rng, options?)` исполняет один полный ход юнита,
включая оба последовательных слота, фазовые эффекты и все независимые последствия.
`runNight(...)` повторяет шаги до completed/defeat. Функции ожидают разрешённую границу
хода: активный MOVE/ход и незафиксированное HP=0 отклоняются. Снимок NightState вместе
с данными runtime, DamageState и RNG можно сохранять между шагами; сами очереди не сохраняются.

Следующий участник читается из актуальной order с исключением уже походивших в раунде ID.
Удаление погибшего не смещает курсор через следующего участника. Призванный получает
новый ID и первый ход в хвосте текущего раунда, сохраняя место дальше. Ловкость,
изменившаяся после старта ночи, не вызывает нового броска/сортировки инициативы.

## Граница раунда и завершение

По решению автора ENG-30 (spec v0.67) поражение проверяется только после полного раунда.
Даже если живых защитников не осталось между ходами, остальные участники и новые
призванные юниты получают положенные ходы. DEATH/SUMMON могут вернуть защитника до проверки.
Если после всех ходов и последствий живых защитников нет — defeat.

Гибель всех врагов не сокращает ночь. В оставшиеся раунды защитники продолжают свои ходы,
включая TURN_START и продолжающие действовать эффекты. После 13-го раунда сначала проходит
проверка поражения. Если защитник остался, ночь становится completed и оставшиеся живые
враги удаляются с карты/из очереди как исчезнувшие, без снижения HP и без DEATH.
Эта техническая последовательность проверена отдельными сценариями конца 13-го раунда.

Постоянные записи эффектов сохраняются, в том числе у исчезнувших владельцев; автоматически
не очищаются и локальные счётчики. Повторно использовать ID такого владельца для новой
сущности нельзя; общий SummoningState и проверка ownerId при призыве сохраняют идентичность.
Индивидуальное знание ловушек очищается на старте новой ночи и при её завершении.
Специальной фазы NIGHT_END и автоматического лечения/отката характеристик нет.

## Политика и наблюдение

Базовый вручную заданный сценарий знает всех живых врагов внутри здания; наружные исключены.
`getOptions(ownerId)` может явно задать knownEnemyIds и ограничения движения/LOS. Эти же
ограничения получает обнаружение ловушек, а его RNG всегда берётся из общего потока ночи.
Наблюдение исходов существующего runtime.trapDiscovery сохраняется.

`createTurnOptions({ ownerId, round, turn })` подключает обычные наблюдатели действий/фаз
и журналируемую AttackQueue через API actions. onRoundStart/onTurn/onRoundEnd/onFinish
дают последовательные границы для журнала, не меняя симуляцию. После технической ошибки
state.failed запрещает продолжение частично разрешённой ночи. Повторный шаг завершённой
ночи ничего не меняет и не расходует RNG.

Результат completed означает пережитую ночь, а не завершение кампании. Дневные события,
награды, подготовка следующей ночи и клиентский API остаются вне этого домена.
