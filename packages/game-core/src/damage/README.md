# Урон по клетке

CELL_DAMAGE — самостоятельное JSON-событие с kind, id, cell и amount. У него нет владельца, обязательного sourceId или списка операций способности. createDamageState хранит счётчик ID; createCellDamage копирует клетку и создаёт новый damage:N. Счётчик сохраняется вместе с симуляцией, событие ставится в очередь один раз.

createDamageQueue исполняет способности и события через один EntryQueue. Созданное внутри эффекта событие ждёт всех его операций, затем идёт перед ранее ожидавшими элементами в порядке создания. Жизнь владельца проверяется только для обычных эффектов; смерть атакующего не отменяет CELL_DAMAGE. Прежняя ExecutionQueue остаётся совместимым адаптером для эффектов. Через createQueue эту очередь можно подключить к runUnitTurn.

Операция create_damage_event использует только семантический selector cell текущего контекста и числовое amount. Абсолютные координаты в контент-селекторе не вводятся. Если контекстной клетки нет, операция пропускается; после неё продолжаются остальные операции. Для этой операции нужна createDamageQueue: обычная очередь без сервиса независимых событий явно сообщает об ошибке настройки. modify_hp по-прежнему меняет HP синхронно, без создания события и без сопротивления.

При разрешении события определяется нынешний повреждаемый обитатель клетки: живой юнит либо закрытое укрепление. Пустая клетка, ловушка без HP, открытый или разрушенный проём урон не получают. Юнит в открытом проёме является целью вместо сохранённого слоя проёма. Сопротивление читается при применении: hpLoss=max(0, amount-resistance), HP=max(0, HP-hpLoss). hpLoss сохраняет полную величину, даже если она больше оставшегося HP.

После события фиксируется смерть юнитов через ENG-12. Укрепление при нуле HP становится destroyed; его свойства и локальные эффекты сохраняются, собственный DEATH получает зафиксированную клетку. Повторное событие не запускает его смерть снова. Открытие, ремонт и остальные операции проёмов относятся к ENG-18. Здесь нет повторных боевых бросков или нового стека on_damaged.

resolveCellDamage возвращает outcome и подготовленные эффекты смерти для встраивания в планировщик. createDamageQueue вставляет их автоматически и может передать outcome наблюдателю для журнала. Пустая клетка даёт targetId=null, hpLoss=0 и null для HP. У события нулевой исходный урон допустим. amount сохраняет исходную величину, resolvedAmount — число после модификаторов.

## Числовые модификаторы

createDamageModifiers создаёт отдельное JSON-хранилище стеков по ID события. Для внешнего добавления модификаторов передайте его в createCellDamage четвёртым аргументом и в createDamageQueue пятым. Можно явно зарегистрировать ID через registerDamageEvent. Повторная регистрация ожидающего события не очищает его стек. Само событие ставится в очередь один раз; его ID не переиспользуется.

addDamageModifier принимает только relative с целым знаковым value или absolute с целым value>=0. Запись копируется и не содержит операций/обработчиков. У отсутствующего или уже разрешённого ID добавление возвращает false. Стек снимается синхронным pop-циклом: absolute присваивает, relative прибавляет с обрезанием до нуля после каждой записи. Затем стек удаляется. Только после арифметики определяется нынешняя цель и вычитается её сопротивление. Даже пустая клетка потребляет стек события.

Операция add_damage_modifier адресует конкретный event.id либо context_damage — damageEventId исходной атаки/защиты в её контексте. Параметр value может читать разрешённое числовое выражение, но в стек попадает уже рассчитанное целое число. Создание дополнительного CELL_DAMAGE не меняет исходный ID контекста и не переносит на новое событие модификаторы. Без доступного контекстного ID операция пропускается; модификаторы не становятся событиями и не могут порождать другие модификаторы.

## Резервирование события атаки

`DamageQueue.createDamageEvent(cell, amount)` резервирует ID и стопку модификаторов,
не ставя событие в очередь. Это позволяет домену `combat` сначала разрешить фазы исхода,
а затем добавить независимый урон через `enqueue`. Используется то же хранилище, что
и у операций очереди; дополнительный экземпляр очереди для атаки не создаётся.
