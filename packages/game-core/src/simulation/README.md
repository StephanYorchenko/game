# Запуск симуляции без UI

`@deathwarriors/game-core/simulation` — публичная точка входа для одной ночи.
Использует существующие правила AI, общую очередь последствий и единый seeded RNG.
Ядро не обращается к браузеру, файловой системе или часам.

## Вход и подготовка

`createSimulation({ seed, content, scenario }, options?)` создаёт независимую сессию:

- `seed` — целое uint32, включая 0;
- `content` — JSON ContentPack из домена content;
- `scenario.world` — подготовленный WorldState v1: карта, сущности, текущие HP,
  характеристики, маски и ключевые слова. Эти значения сохраняются, а не заменяются
  начальными характеристиками определения;
- `scenario.openings` — массив `{ id, definitionId }`: ровно одна связь для каждой
  двери/окна карты. У структур мира нет собственного definitionId. Вид определения
  должен совпадать с проёмом; стены не требуют связи.

Определения юнитов/ловушек берутся из их definitionId. Их способности и способности
связанных проёмов создаются как новые экземпляры эффектов в порядке сценария/контента.
Очереди, временные счётчики и порядок ходов на вход не принимаются. Это новый запуск,
а не загрузка произвольного сохранения: активные эффекты предыдущей ночи нужно сохранять
отдельным будущим контрактом. Знание ловушек очищается на границах ночи по правилам night.

Вход целиком проверяется и копируется до создания ночи/расхода RNG. Ошибки схемы,
ссылок, неизвестные поля, не-JSON значения и неразрешённые начальные смерти/разрушения
вызывают SimulationValidationError с точным `path`, например
`$.scenario.world.units[0].definitionId`.

Необязательный `options.getOptions(ownerId)` подключает доверенный модуль ограничений
InteractionOptions. Он должен быть чистым и воспроизводимым; по умолчанию используются
правила night, включая знание живых врагов внутри дома. Функции не загружаются из JSON.

## Шаги, снимки и события

`getSnapshot()` возвращает независимый JSON-снимок: версию, contentId, seed, текущий мир,
статус running/completed/defeat/error, номер раунда, число завершённых раундов/ходов,
ID следующего юнита, последний завершённый ход и ошибку либо null. Внутренние очереди,
экземпляры эффектов, RNG и технические счётчики не раскрываются.

`step()` исполняет один **полный ход юнита**, включая оба слота, фазы, реакции,
смерти/призывы и возможную границу раунда/ночи. Это не пауза посреди действия.
`runToEnd()` исполняет остаток ночи. Оба возвращают `{ snapshot, events }`, где events —
только новые записи за этот вызов с исходной непрерывной нумерацией.

Начальная инициатива разыгрывается при создании; её записи доступны через
`getEvents()`, который всегда возвращает копию всего журнала. Чтение данных не расходует
RNG. Пошаговый, полный и смешанный запуск при одинаковом входе дают одинаковые снимки
и журнал. События включают начало/конец ночи и раундов, ходы, фазы, действия, RNG,
операции, урон, смерти и обнаружение ловушек.

Мир и полный журнал предназначены для диагностики и доверенного адаптера клиента:
они могут содержать скрытые позиции и известные ловушки. Все события имеют
`visibility: "internal"`; перед показом игроку адаптер должен построить проекцию
по правилам видимости. Публичность API не означает доступность всех данных игроку.

`reset()` повторно создаёт исходную ночь с тем же seed, эффектами и счётчиками,
возвращая начальный снимок и весь новый начальный журнал. Мутации входа или ранее
полученных объектов не влияют на сессию и reset.

После completed/defeat повторные step/runToEnd ничего не меняют и возвращают пустые
события. Ошибка динамической формулы/исполнения даёт статус error и simulation_error;
продолжение запрещено до reset. Снимок ошибки диагностический: атом мог исполниться
частично, автоматического отката нет. Повторный вход в исполнение/reset из обработчика
запрещён.

## Пример

Из корня репозитория:

```sh
pnpm example:simulation
```

Команда собирает ядро и запускает example.mjs в Node без браузера. Он загружает
минимальный ContentPack и example.json, создаёт сессию с seed 33 и печатает краткий
результат полной ночи. В сценарии есть защитник, враг, дверь и ловушка; начальное
ожидание защитника обусловлено отсутствием безопасного полного пути за ловушкой.

```ts
import { createSimulation } from "@deathwarriors/game-core/simulation";

const session = createSimulation({ seed: 33, content, scenario });
const initial = session.getSnapshot();
const initialEvents = session.getEvents();
const firstTurn = session.step();
const remainingNight = session.runToEnd();
const restarted = session.reset();
```

Контракт одинаков для Node-примера и браузерного адаптера; чтение JSON с диска
остаётся только в исполняемом примере, вне TypeScript-реализации ядра.
