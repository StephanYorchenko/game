# Размещение и призыв

`@deathwarriors/game-core/summoning` создаёт нового юнита или ловушку. Декларативная
операция `place_entity` содержит `target: { kind: "cell" }` и `template`: тип, definitionId,
начальные характеристики/маску/сторону/ключевые слова юнита и массив `effects`.
ID, жизнь и позиция исходной сущности не копируются. Клетка берётся из контекста фазы,
а не из абсолютных координат конфига. Нет контекста — операция пропускается.

`runtime.summoning = createSummoningState()` хранит сохраняемый счётчик `entity:N`.
Успешное размещение получает новый ID, не совпадающий с существующими сущностями,
погибшими юнитами, владельцами эффектов или очередью. Неудача не расходует ID.
Счётчик нужно сохранять вместе с миром и эффектами; создание нового счётчика посреди
сохранённой симуляции не поддерживается. Шаблон и эффекты копируются и валидируются
до изменения мира. Ошибка конфигурации — исключение, невозможное размещение — `false`.

На момент исполнения проверяются границы, занятость и блокирующая структура; защитник
может появиться только внутри. Применяются ограничения ночной модели WorldState:
открытый/разрушенный проём не блокирует клетку. Дневная расстановка — другой сценарий.
Вытеснения, альтернативного поиска и воскрешения нет. Размещение меняет мир сразу,
поэтому следующие операции того же эффекта видят новую сущность. Неудача одной операции
не отменяет остальные. Низкоуровневый `placeEntity` возвращает причину отказа.

Порядок призыва согласован 05.11: юнит всегда вставляется **в конец текущей очереди**, впервые
ходит **в конце текущего раунда**, затем сохраняет место в последующих раундах. Инициатива
не перебрасывается. Вызывающий цикл раунда должен читать актуальную очередь до её конца,
а не заранее фиксировать её длину. Полный цикл ночи подключается в ENG-30.
Ловушка не получает ход и в очередь юнитов не добавляется. Других режимов вставки нет.

Эффекты шаблона принадлежат новой сущности. Её снимок `SUMMON` ставится в текущую очередь
как последствие после всего породившего эффекта; сохраняется общий порядок последствий.
Если новая сущность погибла до начала обычного SUMMON-эффекта, он пропускается по правилу
живого владельца. `createDeathQueue` и `createDamageQueue` поддерживают операцию через
общий обработчик размещения. Прямой интерпретатор требует сервис `OperationEvents.placeEntity`.
Сам `placeEntity` возвращает SUMMON-эффекты, не запускает их внутри операции.
